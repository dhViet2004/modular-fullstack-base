## 1. Quy ước bằng chứng và lỗi MCP

- `DETAIL_OK`: context có thông tin giao diện/style/layout và screenshot đã xem. Không dùng screenshot làm asset triển khai.
- `Q_REJECTED`: đã gọi context/screenshot nhưng MCP từ chối vì quota; node mới chỉ có inventory.
- `Q_DEFERRED`: chưa gọi context cho frame sau khi xác nhận quota chặn mọi read tool; node mới chỉ có inventory. Không tuyên bố đã thử hoặc đã đọc những frame này.
- Native/variables bổ sung có trạng thái riêng: Forms/Data/Security đã có context/screenshot nhưng native properties bổ sung bị chặn. Dump toàn bộ variables chưa hoàn thành.

Endpoint hệ thống ngoài bảng business: `GET /health`, `GET /ready`, `GET /api/v1`. Không suy ra màn hình quản trị hạ tầng từ những endpoint này.

Các contract có ảnh hưởng trực tiếp tới UI:

- Roles/permissions hiệu lực lấy từ `GET /auth/me`; catalog có permission không đồng nghĩa đã có endpoint sử dụng permission đó.
- Catalog cấp cùng 7 permission cho ADMIN và SUPER_ADMIN, nhưng cấp/gỡ ADMIN còn kiểm tra role SUPER_ADMIN ở backend. `roles:manage` đơn lẻ không đủ.
- Email policy kiểm tra role SUPER_ADMIN, không kiểm tra `roles:manage` hoặc một permission `settings:*` chưa tồn tại.
- Self account/sessions/files yêu cầu authentication; file/session ownership được xử lý trong service, không có gate `files:*`/`sessions:*` trong catalog hiện tại.
- `GET /users` trả toàn bộ list; không có query schema search/pagination và không có endpoint `GET /users/:id`. Drawer có thể dùng record đã tải sau khi spec fields được đọc.
- Audit query hỗ trợ `cursor`, `limit` (1–100, mặc định 50), `action`, `actorUserId`. Chưa có filters theo date range/outcome được khai báo trong schema. Frontend hiện chỉ truyền cursor và limit.
- Files upload/update dùng binary body và headers `X-File-Name`, `X-File-Content-Type`, không phải multipart FormData. Giới hạn source: 5 MiB/tệp, 10 tệp/user.
- `PATCH /files/:id` tạo file mới, xóa record cũ và trả ID mới. UI thay thế phải cập nhật ID/record sau response; không giả định ID giữ nguyên.
- Sessions response có `id`, `createdAt`, `expiresAt`, `current`; không tự dựng dữ liệu device/IP nếu response không có.
- OAuth bắt đầu bằng browser navigation tới backend; backend callback đặt refresh cookie rồi redirect frontend `/oauth/google/callback`; frontend gọi refresh/me. Không đưa access token vào URL.

## 8. Request flow hiện tại đã trace

### Lấy user và quyền

```text
GET /api/v1/auth/me
→ app.ts /api/v1 → routes/index.ts /auth
→ auth.routes.ts → session.routes.ts
→ authenticate → sessionController.me
→ sessionService.me
→ Prisma user + getUserAccessContext → access.repository → Prisma
→ successResponse({ user, access })
→ auth.api.getCurrentUser → AuthProvider
→ getPostLoginPath / getNavigationItems → UI
```

### Cấp/gỡ ADMIN

```text
PATCH /api/v1/users/:userId/roles/admin
→ user.routes.ts
→ authenticate → authorize(roles:manage) → assertUserIsSuperAdmin
→ validateParams → validateBody
→ setAdminRoleController → userService.setAdminRole → Prisma
→ successResponse({ enabled })
→ AdminUsers mutation → invalidate users query
```

### Email policy - ngoại lệ layer đã có

```text
GET/PATCH /api/v1/system/email-verification
→ system.routes.ts
→ authenticate → assertUserIsSuperAdmin
→ handler/schema parse ngay trong route
→ systemService → Prisma systemSetting
→ successResponse({ enabled }) → EmailVerificationSetting
```

### Authentication state

| State | Điều kiện | User/token và UI |
| --- | --- | --- |
| `loading` | Restore ban đầu hoặc retry thủ công | Khi chưa có user: loading; khi có user: giữ shell/content, Button retry pending |
| `authenticated` | Refresh + /me hoặc login + /me thành công | Token chỉ trong memory; cờ `corestack.session-established=true` trong sessionStorage |
| `guest` | Refresh trả `401 INVALID_REFRESH_TOKEN/REFRESH_TOKEN_REUSED` mà không có bằng chứng phiên trước; hoặc logout chủ động | Không render expired; logout xóa token/cờ/cache |
| `expired` | Hai mã credential trên, đúng endpoint refresh, có user/bằng chứng đã đăng nhập trước | Xóa token/user/query cache; thay trang protected bằng Session Expired |
| `restore-error` | Network/5xx, unknown 401 hoặc /me lỗi sau refresh | Không suy ra guest/expired; giữ user/token/cache đã có, cho retry và giữ nội dung mounted |

Cờ sessionStorage chỉ là bằng chứng UI theo tab, không phải credential hoặc authorization. Nếu storage bị chặn, vẫn giữ bằng chứng trong memory cho tab hiện tại; sau reload không có bằng chứng thì xử lý bảo thủ như guest khi credential bị từ chối. AuthProvider vẫn là nguồn state duy nhất. Interceptor báo lỗi refresh qua native event, vẫn single-flight/retry tối đa một lần; logout abort và bỏ kết quả refresh cũ, không kích hoạt expired.
